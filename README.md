# ✈️ FlightAI Assistant

**An AI-powered airline customer support assistant that uses tool calling to look up real ticket prices from a database.**

Most chatbots can only answer from what the model already "knows", which means they guess, or worse, make things up. FlightAI Assistant is different: when a customer asks about a flight, the model **calls a Python function** that queries a SQLite database, then answers with real, accurate data.

> **Customer:** I need a flight to Paris.
> **FlightAI:** A return ticket to Paris costs $573.

This project demonstrates one of the most important patterns in modern LLM engineering: **giving language models tools**, the foundation of AI agents.

---

## ✨ Features

- 🛠️ **Tool calling**: the model decides when to call `get_ticket_price` and uses the result in its answer.
- 🗄️ **SQLite database**: ticket prices are stored and queried from a real database, not hard-coded in prompts.
- 🔁 **Multi-step tool loop**: handles multiple and chained tool calls before giving a final answer.
- 💬 **Conversation memory**: follow-up questions keep their context.
- 🔌 **Provider-flexible**: works with Groq in the cloud or Ollama locally via the OpenAI-compatible API.
- 🖥️ **Gradio chat UI**: a clean web interface, ready in one command.
- 🧩 **Extensible design**: add a new tool with one file and one line in the registry.

## 🧠 How it works

```
User message
     │
     ▼
┌──────────────┐   needs data?   ┌──────────────────────┐
│     LLM      │ ──────────────▶ │  get_ticket_price()  │
│ (Groq/Ollama)│ ◀────────────── │  queries SQLite DB   │
└──────────────┘   tool result   └──────────────────────┘
     │
     ▼
Final answer to the user
```

1. The user's message is sent to the LLM together with the list of available tools.
2. If the model needs data, it responds with a **tool call** (e.g. `get_ticket_price(destination_city="Paris")`) instead of text.
3. The app runs the matching Python function and sends the result back as a `tool` message.
4. The model uses that result to write its final, accurate reply.

## 🚀 Getting started

### 1. Clone the repository

```bash
git clone https://github.com/<your-username>/flightai-assistant-with-tools.git
cd flightai-assistant-with-tools
```

### 2. Install dependencies

```bash
uv sync
```

### 3. Configure your API key

Copy the example environment file and add your key:

```bash
cp .env.example .env
```

```env
GROQ_API_KEY=your_groq_api_key_here
```

> 💡 **Prefer running locally?** Install [Ollama](https://ollama.com/), pull a model that supports tool calling (e.g. `ollama pull llama3.2`), and point the client to `http://localhost:11434/v1`. No API key needed.

### 4. Seed the database

```bash
uv run seed-db
```

You should see: `Seeded database with 8 cities.`

### 5. Run the app

```bash
uv run start
```

Open **http://127.0.0.1:7860** and start chatting. ✈️

## 🧩 Adding a new tool

Tools are designed to be plug-and-play. To add one (for example, `book_flight`):

1. Create `tools/booking.py` with the function and its JSON schema side by side:

   ```python
   def book_flight(destination_city: str, passenger_name: str) -> str:
       ...

   schema = {
       "type": "function",
       "function": {
           "name": "book_flight",
           "description": "Book a return flight for a passenger.",
           "parameters": {...},
       },
   }
   ```

2. Register it in `tools/registry.py`:

   ```python
   TOOLS = {"get_ticket_price": get_ticket_price, "book_flight": book_flight}
   TOOL_SCHEMAS = [price_schema, booking_schema]
   ```

That's it: the chat loop picks it up automatically.
